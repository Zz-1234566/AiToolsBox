01

工作流运行页 · 四种状态

同一条信息骨架的四个状态：待运行 → 运行中 → 运行成功，以及异常分支 第 3 步失败 · 已中断。四屏并排对照，是这一页的设计评审面。

02

这一版自己的东西

借了「节点连线会亮」这个直觉，但落地形式和布局完全不同 —— 不做横向节点画布，改成移动端能单手读懂的竖向能量轨道。

1两层信息：剖面看全局，轨道看细节
顶部 流程剖面条 一行五个点，回答"我在第几步"；下方竖向节点链回答"每步发生了什么"。不用滚动就能定位，节点再多也不迷路。
2连线本身就是状态
轨道四态：绿实线 已通过、蓝色流光 正在跑、红线 断点、灰虚线 未执行。扫一眼连线就知道流程断在哪，不用逐条读文字。
3失败即断，下游显式「已阻断」
不是把后面全部灰掉。失败节点红环 + 红色错误框，下游标 已阻断，因果关系一眼可见 —— 哪些产出物这次没拿到，清清楚楚。
4耗时账本
HUD 用等宽字体显示总耗时，每个节点标自己花了多久（后端存毫秒 costMs，展示层换算成 X.X s）。慢在第几步、慢了多少 是多步任务最常被问的问题，直接写在脸上。
5输入 → 输出同卡承载
节点的输入输出与状态放在同一张卡里，不另开详情页。链路排查时上下文不丢，也不打断流程感。
6日志独立成块，但沿用浅色
页面底部一条运行日志，用 --bg-page 与白色卡片区分开（对齐 03-页面-08 处理步骤列表的既有做法），保持全页浅色一致，不引入规范外的深色块。
7历史列表也用迷你轨道
每条记录底部一条五点进度条，失败记录用红点标出断在哪一步并写明"断在第 3 步"。不点开也能判断要不要点开。
8克制动效
同屏同时运动的元素 ≤5 个，全部只用 transform / opacity。无缩放、无弹跳，与 06-动效规范.md 一致；失败态红环为静态，不做任何旋转。
03

历史运行页 · 列表

顶部三格统计（跑过多少次 / 成功率 / 平均耗时），胶囊 Tab 分状态筛选。列表项把迷你进度条和失败原因直接摊在卡片上 —— 大多数时候不用点进详情就能判断。

04

运行详情页 · 回放

结果卡给结论（成败 + 总耗时 / 完成节点 / 输入文件），紧跟一张输入快照（失败时立刻能回看「我当时传了什么」），下面是同一条竖向轨道的静态回放 —— 和运行页长得一样，用户不需要再学一套视觉语言。

字段对照本设计稿每块信息对应的后端字段
FIELD MAPPING
输入快照
sys_workflow_run.input_snapshot —— 快照卡列出本次运行上传的文件与文本，可点开原文件
运行级报错
sys_workflow_run.error_msg —— 取顶部红色 alert，说明整个运行为什么中断
节点级报错

节点耗时
node_results[nid].costMs —— 后端存毫秒，前端 /1000 → toFixed(1) 后显示；总耗时取各节点求和
运行状态
sys_workflow_run.status —— 成功 / 失败 / 运行中，决定历史列表的状态筛选与迷你轨道断点
