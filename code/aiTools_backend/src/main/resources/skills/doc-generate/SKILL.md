# 撰写并导出办公文档

## 适用判断
- 用户说「帮我写一份…」「整理成文档」「出一份方案」→ 用本技能
- 用户说「把这份文档的第 X 段改一下」→ 不用本技能（那是 doc-edit 的活）

## 流程

### 第 1 步：收集素材
| 输入形态 | 动作 |
|---|---|
| 上传了文件 | 逐个调用 `doc-to-text` 取纯文本 |
| 直接给了文字 | 直接用 |
| 提到"项目/代码"但没有文件 | 先问：能提供 README 或功能清单吗 |

素材要有：做什么、给谁用、核心功能、技术方案、进展。

### 第 2 步：定大纲（不写正文）
按下列结构输出，**只给标题**：

```
1. 项目背景与目标
2. 需求分析
3. 总体设计
   3.1 架构设计
   3.2 数据设计
4. 核心功能实现
5. 技术难点与解决方案
6. 测试与部署
7. 总结与展望
```

用户没指定结构时用上面这套；指定了就照用户的。

### 第 3 步：逐章生成
- 每章 400-800 字，**一次只生成一章**
- 生成前带上：大纲 + 已写章节的术语表（保证前后一致）
- 允许 Markdown：标题、列表、表格、加粗

### 第 4 步：合并渲染
调用 `doc-render`：

```json
{"content": "<整篇 Markdown>", "template": "project-doc", "title": "项目介绍书"}
```

### 第 5 步：交付
```json
{"file":"file_1","name":"项目介绍书.docx"}
```
并回复：文档已生成，共 N 页，可直接下载。

## 标题层级（严格按此映射）
| Markdown | 含义 | 排版 |
|---|---|---|
| `# 第一章 绪论` | 章标题 | 宋体 14pt 加粗 居中 |
| `## 1.1 课题背景` | 节标题 | 宋体 12pt 加粗 |
| `### 1.1.1 子标题` | 小节 | 宋体 12pt 加粗 |

**不要用 `#` 写文档名**，文档名由 title 参数传入。

## 排版规范（套用学校论文模板）
| 元素 | 规格 |
|---|---|
| 页面 | A4，上下 2.30cm，左 3.17cm，右 2.59cm |
| 正文 | 宋体 12pt（小四），行距 1.5，首行缩进 2 字符 |
| 西文数字 | Times New Roman |
| 章标题 | 宋体 14pt 加粗，居中 |
| 节标题 | 宋体 12pt 加粗 |
| 表格 | 表头浅灰底加粗，字号 10.5pt，边框细线 |
| 代码 | Consolas 11pt，浅灰底 |
| 列表 | 项目符号缩进，不首行缩进 |

## 写作规范
- 中文书面语，不用"我们"开头的口语
- 每个小节先给结论，再给论据
- 表格用于对比（技术选型、功能清单），不要滥用
- 不用 emoji、不用感叹号
- 术语首次出现给出全称
- 单段不超过 200 字，超过就拆分

## 反例（不要这样）
- ❌ 一次生成 8000 字（必然断章、前后不一致）
- ❌ 没有素材硬编内容（先问用户要资料）
- ❌ 把整篇塞进一个表格
